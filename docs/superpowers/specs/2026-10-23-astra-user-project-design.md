# ASTRA по project ID из диалога

Пользователь может назвать project ID и разрешить агенту обращаться к ASTRA при
пробелах в понимании продукта, зависимостей или Istio-конфигурации. Адреса и ключ
задаются оператором. Сервер не требует отдельного включения интеграции и не
требует заранее вписывать project ID для локального stdio-клиента.

Выбранный подход: доступность определяется настройками URL и credential_env;
проект остаётся явным параметром каждой product-context операции. Клиентский
агент запоминает сообщённый пользователем ID и использует его без catalog-запроса.
Это соответствует запросу пользователя и сохраняет существующий API. Альтернатива
с default_project_id оставляет зависимость от конфигурации оператора; новый
серверный выбор проекта добавил бы ненужное состояние и отдельный инструмент.

- `astra` и `enabled` необязательны. Нет конфигурации — нет внешнего I/O.
- Явное старое `enabled:false` сохраняет запрет для совместимости (решение
  реализации); в новых примерах переключателя нет. `enabled:true` по-прежнему
  требует полную конфигурацию. Частичная конфигурация отклоняется.
- В stdio отсутствие allowed_projects использует права upstream API-ключа;
  заданный список сужает доступ, явный пустой список запрещает все проекты.
- HTTP никогда не получает неограниченные права из отсутствующего глобального
  списка: обязательны назначения `bindings[].astra_projects`.
- ID из запроса не расширяет назначенные права. 403 не вызывает перебор проектов.
- Без ID ask/search/source не обращаются к сети. Catalog нужен только когда
  пользователь просит выбрать проект, а не перед каждым вопросом.
- Агент вызывает ASTRA по необходимости после согласия пользователя/указания ID,
  не передаёт raw dumps/логи/секреты и проверяет ответ по live evidence.
- Go-сервер остаётся без LLM. Его capabilities показывают готовность конфигурации;
  наличие credentials и реальный доступ проверяются только при запросе.
- MCP contract остаётся 2026-10-22, prompt bundle получает версию 2026-10-23.

Проверка: конфиг без enabled/allowlist; прямой ask с ID из диалога без catalog;
явный запрет, пустой allowlist, HTTP scope, отсутствие сети без ID/настроек;
сужение principal scope и независимость основного diagnostic job.
