# Проверка контракта и качества диагностики

[Навигация](README.md) · [Примеры API](examples/tool-cases.json)

## Что проверяется в этом комплекте

Документы и схемы проходят проверку JSON/YAML, внутренних ссылок, prompt manifest,
input/output examples и согласованности tool names. Это проверка артефактов,
не тест работающего MCP или реального кластера. Примеры синтетические.

`validate_contracts.go` проверяет схемы/примеры через уже используемый проектом
`github.com/google/jsonschema-go`, а не через самописную имитацию JSON Schema:

```bash
go run docs/design/validate_contracts.go
```

Проверка включает положительные и намеренно невалидные examples. Отдельно
проверяется timezone/start<end у окон в примерах как семантика; ownership/state/idempotency
проверяются при реализации, а не объявляются доказанными формой JSON.

## Live-набор для оценки покрытия

Начальная цель — 30–50 воспроизводимых случаев в поддержанном scope, включая
здоровые и намеренно неполные наблюдения. Для каждого сохранить seed/configuration,
версии среды, известную причину, ожидаемые evidence, допустимые unknown и запрещённые
ложные объяснения. Отдельные наборы для разработки и итоговой оценки уменьшают
подгонку правил. Фикстуры допустимы для unit tests и не создают offline-продукт.

Метрики раздельные: обнаружение симптома, локализация участка, точность заявленных
confirmed причин, корректное воздержание, per-pod coverage, latency, API calls и
объём данных. Отсутствие доказанной причины не считается успехом root-cause test
только потому, что найден HTTP 503. Знаменатель включает только согласованный scope.
Реальное число/процент публикуется после прогона с описанием выборки.

## Диалоговые сценарии агента

Проверить хотя бы: неоднозначный ввод; выбор и продолжение очереди; неполный сбор;
нет событий; not-ready proxy; просьба остановиться; ASTRA выключена; ASTRA
противоречит live evidence; после исправления нет трафика; потеря контекста клиента.
Проверять фактические tool calls, сохранение выбранного окна и отсутствие
необоснованного повышения confidence, а не только похожесть финального текста.

## Граница текущей проверки

В этом документе перечислены критерии будущей реализации. Нет нового kubeconfig,
реальных access logs или фактического подключения к ASTRA. Live smoke, нагрузочные
испытания и клиентские диалоги на новом API ещё не выполнялись.

## Проверка артефактов 22 октября 2026

Выполнены: разрешение input/output схем 11 tools, 20 положительных/отрицательных
контрактных примеров, пример конфигурации и два отрицательных варианта (HTTP без
auth, enabled ASTRA без настроек), совпадение structuredContent и text в JSON-RPC
примере, hashes семи модулей, внутренние ссылки, JSON/YAML syntax и отсутствие
exec/Secrets/write-workload прав в новом RBAC-примере. Проверка завершилась успешно.

Серверный Go-код не изменён. Этот результат подтверждает согласованность артефактов,
но не выполнение нового алгоритма или работу внешних подключений.
