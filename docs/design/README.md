# istio-diagnostics-mcp · проектный комплект

**Редакция:** 22 октября 2026 · **Контракт:** `2026-10-22` · **Статус:** проект для ревью.

Go MCP-сервер помогает выяснить, почему приложение не может обратиться к другому
приложению внутри Kubernetes или почему к нему не могут подключиться. Он собирает
живые данные, проверяет обе стороны и объясняет вывод через доказательства.

> Этот комплект описывает переработку текущего проекта. Новые инструменты ещё не
> реализованы. Старый исполняемый прототип вынесен в архивную Git-ветку; в рабочем
> дереве остались артефакты и их проверка. [Основа переработки](rewrite-baseline.md).

## Основные договорённости

- Один кластер, Istio sidecar, east-west cluster-local, включая разные namespace.
- Запуск снаружи кластера по kubeconfig; локальный stdio или удалённый Streamable HTTP.
- Live read-only: Kubernetes get/list, proxy logs и временный port-forward на 15000.
- Все доступные реплики участников, выбранный пользователем период; default — 15 минут.
- Симптомы → выбор связи → проверка обеих сторон → результат → оставшаяся очередь.
- Клиентский агент ведёт диалог. Go-координатор собирает данные и выполняет проверки.
- ASTRA выключена по умолчанию и не нужна для основной диагностики.

## Как читать статус

| Обозначение | Значение |
|---|---|
| Согласовано | Прямое решение пользователя; реализация ещё может отсутствовать |
| Предложено | Конкретное техническое решение этого комплекта, требующее ревью |
| Реализовано в прототипе | Подтверждено чтением кода; не означает проверку на настоящем кластере |
| Открыто | Неизвестный параметр окружения; указан безопасный вариант поведения |

В [архивном прототипе](https://github.com/daybrk/istio-diagnostics-mcp/tree/archive/go-mcp-v0.1)
есть локальный разбор Envoy v3, ограниченный trace одного proxy,
отдельные конфликты маршрутов, сроки доступных сертификатов, namespaced сбор и
разрешение workload. Сессии с очередью, proxy logs, port-forward, HTTP transport,
модульные промпты и ASTRA по этому комплекту ещё не реализованы. Из новой ветки
старый код удалён; правила и тестовые сценарии можно переносить выборочно.

## Источники истины и изменения

1. [Требования](requirements.md) определяют продуктовые ограничения.
2. [API](api.md) определяет семантику; JSON Schema — форму сообщений. Расхождение
   между ними является дефектом документации и блокирует реализацию затронутого API.
3. [Алгоритм](algorithm.md) определяет переходы и требования к доказательствам.
4. Промпты объясняют клиенту этот контракт и не могут расширить его полномочия.

[Первоначальная спецификация](../superpowers/specs/2026-10-22-live-readonly-diagnostics-design.md)
сохранена как обзор с историей договорённостей. Этот комплект детализирует её.
Изменение инструмента требует одновременного обновления схемы, примера, описания и
затронутого промпта. Версия контракта и prompt bundle фиксируется в сессии.

Перед реализацией остаются ревью этого комплекта и отдельный план работ. Документы
и примеры здесь не являются результатами live-диагностики.
