# Требования и журнал решений

[Навигация](README.md) · Статус: продуктовые решения + предлагаемые детали.

## Согласованный объём

| ID | Требование | Проверяемое поведение |
|---|---|---|
| R01 | Go; сервер без собственной LLM | Для основной диагностики не нужен ключ модельного API |
| R02 | Только live read-only | Нет входного пользовательского dump, exec, probes, изменений ресурсов |
| R03 | Снаружи кластера по kubeconfig | Context и доступ проверяются на машине сервера |
| R04 | Port-forward pod:15000 | Чтение встроенных Envoy GET; отдельный handler приложения не создаётся |
| R05 | Sidecar, east-west, один кластер | Внешний участок обозначается как вне покрытия |
| R06 | HTTP/HTTPS/gRPC/TCP | Недоступные поля L7 не выдумываются для TLS passthrough/TCP |
| R07 | Однозначная идентификация | Namespace, workload и направление уточняются только при необходимости |
| R08 | Все pod'ы участников | По каждой обнаруженной реплике виден исход сбора; нет скрытой выборки |
| R09 | Выбираемый период | Относительный или абсолютный интервал; 15 минут только при отсутствии выбора |
| R10 | Только логи `istio-proxy` | Нет автоматического чтения логов приложения, istiod, DNS или CNI |
| R11 | Симптомы и очередь | Пользователь выбирает связь; после результата видит оставшиеся |
| R12 | Указанная пара сразу в работу | Не требуется выбирать её повторно из несвязанных направлений |
| R13 | Короткий вывод, детали по запросу | Причина/неизвестное, evidence, ограничения и следующий шаг |
| R14 | Stdio и Streamable HTTP | Один движок и контракт; binary/kubeconfig расположены на сервере |
| R15 | ASTRA опциональна | Default off; отсутствие/отказ ASTRA не блокирует основную диагностику |
| R16 | Модульные инструкции | Короткое ядро, явные условия загрузки, доступ к модулям через MCP |
| R17 | Чистая основа для переработки | Старый сервер в архивной ветке; новая реализация по контрактам без совместимости со старым API |

Read-only относится к диагностируемым системам. Создание in-memory сессии, HTTP
POST протокола MCP и connect subresource port-forward не являются изменением
workload. Это различие явно отражается в RBAC и MCP tool annotations.

## Предлагаемые уточнения текущего проекта

| ID | Решение | Основание / предел |
|---|---|---|
| P01 | Разбирать access и диагностические сообщения из того же proxy container | Не включать debug и не читать другие контейнерные логи |
| P02 | Продолжать без dump при неготовом proxy | Pod/container/initContainer status, Events и available previous logs |
| P03 | Возвращать resume summary из серверной сессии | Сохраняется только в пределах TTL; после рестарта нет обещания восстановления |
| P04 | Сравнивать новую попытку с предыдущей | Отдельные временные интервалы и версии; без генерации трафика |
| P05 | Версионировать правила и prompt bundle | Не менять интерпретацию старой попытки молча |
| P06 | Ограничивать сбор и ASTRA отдельными бюджетами | Частичный результат с перечнем незавершённых операций |
| P07 | 11 публичных tools в целевом контракте | Восемь ранее предложенных + playbook, cancel и optional product context |
| P08 | Фиксированные диагностические правила с обязательными evidence | Не интерпретировать ответ ASTRA как исполняемый код |

Это предложения для ревью артефактов, а не утверждение, что пользователь отдельно
утвердил каждое имя поля, числовой лимит или каждую проверку.

## Открытые решения и поведение до уточнения

| ID | Что неизвестно | Поведение / что блокируется |
|---|---|---|
| O01 | Версии Kubernetes/Istio/Envoy и реальный формат proxy logs | Capability detection; неизвестный parser/matcher → UNSUPPORTED. Финальная матрица совместимости требует образцов |
| O02 | Вход пользователей удалённого сервиса и Kubernetes identity | Предложен OIDC access-token verifier + явная привязка subject к scope. Общий HTTP-сервис нельзя запускать без выбранной и проверенной модели |
| O03 | Реальные ASTRA URL, transport/auth и mapping продукта | Интеграция off. Ссылки на портал из вложения не используются как endpoint |
| O04 | Способ установления версии продукта в ASTRA | Не считать git HEAD или найденный файл версией работающего образа |
| O05 | Масштаб приложений и приемлемая нагрузка | Начальные лимиты в конфигурации — инженерные предложения, требуют нагрузочной проверки |
| O06 | Нужно ли дополнительно читать Envoy `/stats` | В базовый allowlist не входит. Добавляется отдельным решением; текущее значение counter не равно истории инцидента |

## Что не входит

Ingress от внешнего клиента, внешний egress, ambient, multicluster, UDP,
историческое восстановление удалённых ресурсов/логов, offline-продукт,
автоматическое исправление, node shell/packet capture, активные probes,
постоянный cluster-wide аудит и встроенный агент LLM.

## Негативные гарантии вывода

- Одинаковый номер порта у разных Service не означает конфликт.
- Истёкший неиспользуемый сертификат не является причиной выбранной ошибки.
- Наличие route и endpoint не доказывает сетевую доступность или listening socket.
- HTTP 503, UC, UH, reset или timeout сами по себе не определяют корневую причину.
- Совпадение версии с GitHub issue — повод проверить гипотезу, а не диагноз.
- Нет события в логе назначения — не доказательство места потери пакета.
- Неудача чтения ресурса — не отсутствие ресурса и не отказ приложения.
