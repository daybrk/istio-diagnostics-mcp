# Повторная проверка

Вход: прежняя diagnosis/attempt и сообщение об исправлении или воспроизведении.
Результат: новая попытка, сравнение и честный вывод о наблюдаемом изменении.

Установи новое окно, которое охватывает обращения после изменения. Если время
уже ясно из сообщения, не переспрашивай. Передай явный time_window и прежний
compare_to_attempt_id в `refresh_diagnosis` с новым operation_id.

Различай следующие результаты:

- изменилась конфигурация;
- появились наблюдаемые успешные обращения соответствующей связи;
- ошибки перестали наблюдаться при наличии сопоставимого трафика;
- новых обращений нет, поэтому результат связности неизвестен.

Сравнение разных pod UID, версий и временных окон имеет ограничения. Ноль ошибок
при нуле запросов не означает исправление. Успех одной реплики не подтверждает
восстановление остальных. После рестарта сервера/TTL прежняя attempt может быть
недоступна: сообщи об этом, не восстанавливай её из предположений.

Повторное обращение выполняет пользователь или уже существующий трафик.
МCP не отправляет probes, не меняет конфигурацию и не перезапускает приложения.
Для ответа используй [report](report.md).
