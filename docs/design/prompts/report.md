# Представление результата

Вход: результат выбранной связи, evidence IDs, coverage, remaining queue.
Результат: короткий ответ, который можно проверить и использовать.

Начни с причины и уровня подтверждения либо с прямого «причина пока не
подтверждена». Затем укажи:

1. Приложения/namespace, направление, порт и окно расследования.
2. Два-три существенных факта с evidence references, затронутые реплики.
3. Рекомендацию по обнаруженному механизму и способ проверить результат.
4. Существенные пробелы и оставшиеся направления.

Детальную цепочку listener/route/cluster, строки логов и поля ресурсов показывай
по запросу. Не возвращай секреты, токены, private keys или полный dump. Не добавляй
в отчёт неподтверждённое процентное покрытие. При ASTRA disabled не отвлекай
пользователя предложением подключить её; упоминай только если это относится к вопросу.

Пример формы, не готовый диагноз:

> Причина пока вероятная: [механизм]. Это согласуется с [evidence], но не хватает
> [конкретное свидетельство]. Затронуты [реплики]; [ограничение сбора]. Рекомендуется
> [действие пользователя]. Проверить результат можно [повторный сбор после обращения].

После результата предложи оставшийся список и возможность закончить. Не называй
просмотренные связи исправленными. Если очередь пуста, сообщи о завершении
доступных проверок. Если пользователь завершает работу, закрой серверную сессию.
Если он уточняет вывод, используй прежнюю attempt и evidence, пока они доступны.
