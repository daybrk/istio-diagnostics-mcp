# Чистая основа для переработки

[Навигация](README.md) · Решение пользователя: 22 октября 2026.

Старый серверный каркас удалён из рабочей ветки `feat/go-mcp-v0.1`.
По решению пользователя переработка продолжается в этой же исходной ветке.
Новая реализация должна следовать текущим API-контрактам, алгоритму и границам.
Совместимость со старым API не является требованием.

## Архив

Полный прототип сохранён в
[archive/go-mcp-v0.1](https://github.com/daybrk/istio-diagnostics-mcp/tree/archive/go-mcp-v0.1)
на commit `832578f9f23a44355841fe974a5e89167c6fce6e`. Эта версия содержит код,
тесты, примеры, Dockerfile, прежний RBAC и проектные артефакты до очистки.
Перед удалением `go test ./...` прошёл для всех трёх пакетов с тестами.

Локально создан также tag `prototype/go-v0.1`, но он не опубликован: обычный git
push не имеет credentials, а используемый GitHub-коннектор не предоставляет
операцию создания тегов. Доступная удалённая точка восстановления — архивная
ветка и указанный commit; наличие тега в чужом clone не предполагается.

## Удалено из рабочей ветки

| Область | Причина |
|---|---|
| `cmd/` | Прежний stdio entrypoint и offline CLI не соответствуют целевому flow |
| `internal/server/` | Старые tools и snapshot store заменяются session API |
| `internal/live/` | Сбор через istioctl одного proxy заменяется новым live collector |
| `internal/diagnostics/` | Правила будут переноситься выборочно, без зависимости новой архитектуры от старых моделей |
| `examples/` | Примеры старого offline API относятся к архиву |
| `deploy/` | Прежний RBAC с optional pods/exec больше не предлагается |
| Dockerfile и .dockerignore | Пока нет нового server entrypoint и сборки образа |
| `docs/architecture.md` | Историческая архитектура прототипа доступна в архиве |
| Runtime dependencies в go.mod/go.sum | Оставлена зависимость проверяющего схемы инструмента |

## Сохранено

Весь `docs/design/`, первоначальная спецификация и исследование Istio issues,
Go module path, версия Go, `.gitignore` и Git-история. CI теперь проверяет схемы,
примеры, hashes модулей и ссылки; он не заявляет сборку отсутствующего сервера.

## Выборочный перенос

Подходящие кандидаты: разбор Envoy v3, проверки cluster references, TLS validity,
приоритеты route/filter-chain matching, redaction и соответствующие негативные
тестовые сценарии. Каждый перенос сначала сопоставляется с новым контрактом
evidence, правилами confidence и поддержанными версиями. Старые модели и публичные
tools не копируются автоматически вместе с функцией.

Чтобы посмотреть прежний файл после fetch архивной ветки:

```bash
git fetch origin archive/go-mcp-v0.1
git show origin/archive/go-mcp-v0.1:internal/diagnostics/diagnostics_test.go
```

Этот документ фиксирует подготовительный коммит очистки. Последующая реализация
выполнена в той же исходной ветке; см. [статус](implementation-status.md) и
[план](../superpowers/plans/2026-10-22-live-readonly-implementation.md).
